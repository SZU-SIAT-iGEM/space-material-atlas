# Contributing · 贡献与维护

当前内容基线为 i2026.P0.2，待人工审查。通过 [GitHub 仓库](https://github.com/SZU-SIAT-iGEM/space-material-atlas)提交 issue 或 pull request；内容仍在本机管理端维护，并交付完整 CI 源码包。

## 内容修改

1. 从当前 `content/` 或管理端完整导出队伍资料；不要以旧试导入文件覆盖后续修订。
2. 复用年份和稳定 ID。已有路线计为已纳入图谱；只有名录的队伍为等待增补；未入名录的未来展望不计入正式统计。
3. 保留未修改字段和全部路线。新增节点的粒度参照现有同类队伍，细节保存在双语说明中。共享概念不表示队伍之间存在合作。
4. 通过 [整队导入 skill](../skills/atlas-team-import/SKILL.md) 或管理端检查完整 bundle，查看差异、引用影响，填写原因再应用。
5. 运行 `python manage.py validate` 和 `python manage.py build`；检查中英文本、总图和相关分图、节点说明、搜索、队伍聚焦及 iframe。
6. 记录新增、替换和删除的文案及所在节点；人工审查后按 [版本规则](versioning.md) 保存新的提交。

文案采用第三方客观描述，保留资料中的目标、计划和候选含义。证据、推断依据与待核对事项写在审阅材料中。2026 年起节点各有独立说明，沿用共用的悬浮呈现规则；不加入队伍专属代码。

## 引擎或界面修改

沿用深蓝、浅绿和语义配色，保留原图标、流程方向、分组轮廓和交互。引擎变更需记录实现版本，运行 `node tests/test_layout.cjs`；实际改变布局能力时再运行 `node scripts/benchmark_layout.cjs` 并保存测量结果。

行为变化检查桌面、手机竖屏、横屏和平板，覆盖鼠标、键盘、触控板与手势相关逻辑。明确区分浏览器尺寸模拟、手势逻辑测试和实体设备验证。完整说明见 [maintenance.md](maintenance.md)。

## 文档与发布

更新当前指南中的版本、统计、命令和链接；历史报告保留原始结果，并标明所属阶段。截图保存到 `docs/images/`，记录版本、页面和尺寸。源码中的图片用于文档，不进入静态站点。

运行 `python manage.py export-ci` 生成完整源码，检查新解压目录可构建。发布包不包含 `.state/`、`.venv/`、缓存、密钥或私有草稿。保存的发布快照不可覆盖；文档刷新可作为单独交付，说明内容版本与原快照的关系。
