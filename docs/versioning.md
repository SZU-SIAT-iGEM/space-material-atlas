# 图谱版本规则

版本名称为 `i年份.状态基础图轮次.提交轮次`，例如 `i2026.P0.3`。

- `i2026`：图谱年份。
- `P`：预发布；`R`：正式发布。
- 第一个数字：基础图轮次，从 `0` 开始。
- 最后一个数字：在该基础图上的提交轮次，从 `0` 开始。

同一基础图继续提交时递增末位，例如 `i2026.P0.4`。进入新一轮基础图时可使用 `i2026.P1.0`。确认正式发布后使用对应的 `R` 名称。队伍年份与图谱发布年份分别保存；最新内容可以包含历年队伍。

## 保存与恢复

```sh
python manage.py release i2026.P0.4 --notes "Updated team routes"
```

发布保存完整内容、布局、源码、静态成品与校验和。版本名称写入内容配置、网页和源码清单；版本列表按数字排序。schema_version、依赖版本及 Git commit 各自保留，不替代图谱发布编号。

发布名不能覆盖。修订内容时保存新的提交轮次，保留旧版供年度 Wiki 重建。管理端恢复历史内容会使用当前引擎；如需重建原实现，解压该版本的 `source.zip` 到新目录并运行 `python manage.py build`。

本机草稿和维护事务保存在 `.state/`，不进入源码包，需要单独备份。年度部署记录所用图谱版本和源码 commit；参见 [CI 指南](ci.md)与[托管说明](hosting.md)。
